# Taylor-Couette Flow Benchmark

[![DuMux CI](https://github.com/Sarbani-Roy/taylor-couette-flow/actions/workflows/run-benchmark-dumux.yml/badge.svg)](https://github.com/Sarbani-Roy/taylor-couette-flow/actions/workflows/run-benchmark-dumux.yml)
[![REUSE status](https://api.reuse.software/badge/github.com/Sarbani-Roy/taylor-couette-flow)](https://api.reuse.software/info/github.com/Sarbani-Roy/taylor-couette-flow)

A benchmark for the steady viscous flow between two concentric rotating cylinders (circular Couette flow, Re = 100), compared with the analytical solution on three successively refined grids.

See the [documentation](docs/benchmark-documentation.md) for the problem, its
solution and the metrics.

## Metrics

- **`l2_error_pressure_rel`**: Relative L2 norm of the error between the computed pressure field and the analytical solution; expressed as a dimensionless ratio of the error norm to the reference norm.
- **`l2_error_velocity_rel`**: Relative L2 norm of the error between the computed velocity field and the analytical solution; expressed as a dimensionless ratio of the error norm to the reference norm.
- **`l2_error_pressure`**: Absolute L2 norm of the pressure error (difference between computed and analytical pressure); retains the SI unit of pressure, pascal.
- **`l2_error_velocity`**: Absolute L2 norm of the velocity error (difference between computed and analytical velocity); retains the SI unit of velocity, metres per second.

## Running the benchmark

```bash
mamba env create -f environment_benchmarks.yml
mamba activate taylor-couette-flow-model-validation
python -m pip install -r requirements.txt
docker build -t benchmark dumux/container
apptainer build benchmark.sif docker-daemon://benchmark:latest
export BENCHMARK_CONTAINER=$PWD/benchmark.sif
cd dumux
python run_benchmark.py --benchmark-file ../benchmark/1.0.0/minimal-configurations.json --result-path ./results
```

`run_benchmark.py` runs the Snakemake workflow for every configuration in the
container and packs the runs into an aggregate RO-Crate. The
[DuMux CI](.github/workflows/run-benchmark-dumux.yml) does
the same on every push and checks that every configuration wrote every metric.

## RoHub

The [RoHub Integration CI](.github/workflows/rohub-integration.yml) runs the
benchmark and uploads each run's aggregate RO-Crate to [RoHub](https://rohub.org),
annotated as investigating the benchmark's research object: every Friday to the
development RoHub, and on demand (Actions -> RoHub Integration CI -> Run workflow)
to production if *Upload to production RoHub* is ticked, else development. For
each RoHub it needs the research object's identifier -- the repository variable
`ROHUB_DEV_BENCHMARK_IDENTIFIER` or `ROHUB_PROD_BENCHMARK_IDENTIFIER` (Settings ->
Secrets and variables -> Actions -> Variables) -- and the login as the secrets
`ROHUB_DEV_USERNAME`, `ROHUB_DEV_PASSWORD` or `ROHUB_PROD_USERNAME`,
`ROHUB_PROD_PASSWORD`; benchmantic sets these up when it creates the repository.
Without an identifier it skips the RoHub steps. A manual run can download the benchmark's
resources from RoHub instead of using `benchmark/1.0.0/minimal-configurations.json`.
